# 安装到另一台电脑 / 从本机定制版升级

## 全新安装

只复制源码并按 README 安装。新电脑使用自己的 DSH 模型和订阅凭据；GitHub 包没有任何岗位库或 Key。建议把数据放到独立固定目录，避免以后删除源码时连带删除记录。

## 保留自己的历史记录

1. 在旧电脑暂停原生招聘任务，等待执行结束，退出 DSH。
2. 完整备份旧数据：`data`、`reports`、`logs`。不要在SQLite运行时只复制主文件，WAL里可能仍有事务。
3. 把这些文件夹复制到新电脑的数据根目录，例如 `D:\RecruitmentData`。根目录下面应为 `data\recruitment.sqlite3`，不要多套一层 `data\data`。
4. 在新源码副本运行 Setup，把 `dataRoot` 指向该目录。不要把运行时数据上传 GitHub。
5. 旧版和新版的插件包名相同，不能并排安装。旧电脑上的现有版本无需为下载源码而升级。确实要升级时，通过 DSH 官方插件管理器卸载旧插件，再安装新目录；该操作不要删除数据或重置任务。
6. 插件会按标记复用已有原生任务，避免创建第二个任务。旧电脑也继续运行时，两个电脑各有本地数据库，不会自动同步；选择一台作为日常运行主机并停用另一台任务。

旧数据库的日报路径可能是旧电脑的绝对路径。新版本会在受控的新 `dataRoot/reports` 下按执行ID查找对应报告，不读取新数据根目录以外的旧路径；复制 reports 后可继续在界面查看。数据库状态和来源历史保留。

本仓库不会从旧安装或 DSH 凭据目录自动搜集/导出任何个人数据。只有用户自己明确选择的数据目录才参与迁移。
